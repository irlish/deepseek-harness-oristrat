# Agent Note: 文件监听接收父目录事件

Status: implemented

[English](2026-09-24-local-file-watch-rename-events.md) | 中文

## Problem

在完整测试套件运行期间，macOS 对缺失文件的真实监听有时无法报告从同目录暂存文件重命名创建目标文件的事件。将测试超时从五秒延长到十五秒后，变更流仍未收到事件。直接运行 20 个并发监听时，OS 监听漏报了五次目标事件，而 Chokidar 轮询没有漏报。

## Decision

文件监听继续使用 Chokidar 的非递归父目录监听，并在提供方回调中根据解析后的目标路径筛选收到的事件。开始监听时目标文件缺失，则使用轮询，并采用已校验的 `missingFileWatchIntervalMs` 设置，默认 100 毫秒。已有文件与目录的监听继续使用 OS 事件。

## Alternatives considered

**延长测试超时。** 等待十五秒后事件仍然缺失，延长等待时间不能解决事件交付问题。

**只移除 Chokidar 的同级文件过滤。** 做出该修改后，完整测试套件仍漏报事件，因此回调筛选不能恢复 OS 未送达的通知。

**轮询所有文件监听。** 已有文件可以使用 OS 事件而不持续读取元数据。轮询只用于能够复现创建事件漏报的起初缺失目标。

## Consequences

起初缺失文件的监听在整个生命周期中周期性访问文件系统，文件出现后也如此。Chokidar 会处理被监听父目录中的同级文件事件，而提供方仍只报告选定文件。监听保持非递归，就绪后仍由调用方负责关闭。真实监听集成用例覆盖原子重命名创建缺失的外部文件；适配器测试覆盖轮询选择、间隔校验、同级事件筛选与关闭。
