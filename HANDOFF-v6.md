## What shipped (round 3)

1. **Browser toolbar cleanup (R3-1).** The `.go` submit button — painted black-on-black because its brand background and label tokens resolved to the same dark color — is deleted from `ui-browser-panel`; the address form navigates on Enter alone (the placeholder already said so), and `action.open` left both dictionaries. The gray square over the dock was the `WebContentsView` at stale bounds: `getBoundingClientRect` ran mid-animation during the pane's open transform and no observer fired after settle. Bounds now come from the new `bridge.boundsFromLayout` offset-chain walk (final while ancestor transforms run), pushed on mount, on a 300ms settle timer, and by the existing ResizeObserver/scroll/resize pushers. `attach` also sets a `#ffffff` view background so an unpainted view never shows dark.
2. **Browsing state survives tab switches (R3-2).** `browser-view.ts` keeps one `WebContentsView` per window for the window's lifetime: `hide()` detaches via `removeChildView` behind an `attached` flag without destroying the document, cookies, or history; `open()` idempotently re-attaches the same instance with no reload. The renderer face renames `close` to `hide` (IPC `dsh-desktop:browser-hide`, handler keeps the controller alive); `close` survives only for window teardown.
3. **Codex-style header repo menu (R3-3).** `ui-repo-panel` deletes the sidebar tab registration (definition/RepoTabBody/RepoTitle/RepoPanel) and registers one `conversation.session.header.utilities` entry (id `repo-env`, order 0 — right of the Session ⋯ menu, left of the sidebar corner toggle): `RepoEnvAction` renders a branch-glyph trigger opening a portaled popover (`useAnchoredPosition` + `useDismissOnOutsidePointer` + Escape) with environment rows (change totals or clean note, host, branch with divergence, sources) and a branch submenu: substring search, `menuitemradio` rows with the current branch checked, checkout on pick, and an inline create-and-checkout draft form. Status polls every 4s while open; branches poll only while the submenu is open; mutations are busy-guarded (rows and the create button disable while busy) and close the popover on success or show git's refusal inside the submenu.
4. **gui-repo branch verbs.** `branches` (concurrent `for-each-ref refs/heads` + `rev-parse --abbrev-ref HEAD` after the toplevel probe), `checkout` (`git switch -- <branch>`), `createBranch` (exported `isValidBranchName` guard, then `git switch --create <name>` — no `--`, which switch would read as a start-point). Both mutations share a private `mutate` helper: zero exit → `{ ok: true }`; otherwise `{ ok: false, error }` with git's trimmed stderr, stdout fallback, then `git <verb> failed`. `runGit` now collects stderr. Commit/push remain absent by product decision; branch switching is the namespace's only mutation.
5. **Notes and docs.** New Agent Note `.agents/notes/implemented/feature/2026-09-23-oristrat-header-repo-menu-browser-view-reuse.md` (+zh, pairing recorded); the round-2 note's F3/F4 mechanism facts rewritten in place with cross-links. ## Round-3 decisions worth remembering

- `git checkout -- <branch>` treats the operand as a pathspec; `git switch` is the unambiguous verb for both checkout and create (`--create` reads the next token as the new name, so no `--` there).
- A `WebContentsView` is a native child of the window, not of the DOM: hiding a DOM element cannot retract it; only `removeChildView` stops it painting over the app. Keeping the instance alive across hide/open cycles is what preserves browsing state.
- Offset-chain measurement (`offsetLeft/offsetTop` summed through `offsetParent`) is immune to ancestor transform animations, unlike `getBoundingClientRect`.
- Header seats: `conversation.session.header.utilities` is session-scoped; its `PropsRuntime` supplies `sessionId` + `useSessions`, which is how the menu reads the session workspace `cwd` without new plumbing.
