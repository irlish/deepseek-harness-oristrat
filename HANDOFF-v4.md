## What shipped

1. **Codex-style mode switcher (top-left).** A chip on its own row below the sidebar brand names the deployment mode and opens a two-entry menu: Coding (MSCE-governed engine development) and Work (free-form proposals, PPT, docs). The mode lives in the `oristrat` settings namespace (`mode: coding | work`, default `coding`, seeded in `apps/desktop/seed/settings.yaml`). In Work mode the MSCE norms system-prompt section contributes empty text and the `msce-gate` guard passes every tool dispatch through unexamined; both fail closed to Coding when the settings service is absent. Sessions are shared across modes — nothing is filtered. The chip reads through the settings domain's shared describe mirror (`ctx.settingsScope.bind`), so it adds no cold-boot `settings.describe` RPC and never shows a mode the Host refused. The collapsed rail omits the chip.
2. **Per-model vision declaration.** Both catalog editors on the Models settings page carry a per-row image-input (视觉) checkbox. It writes the adapter-owned modality list explicitly (`input: ['text','image']` / `['text']` for pi-ai routes, `inputModalities` for the DeepSeek catalog). Enforcement stays in the pi-ai adapter: a model whose resolved `input` lacks `image` refuses image content at send time.
3. **Template PPT (Work-only, default off).** The reference-generation bundles `dsh-ppt` + `dsh-ppt-composer` 0.1.1-rc.2 ship as vendored tarballs (`apps/desktop/vendor/ppt`) inside the built-in desktop profile prefix. The hero PPT chip and template gallery come from those bundles and render only while the stored mode is Work — the deployment default is Coding, so the feature starts hidden; the composer dock chooser and accessory entries follow the same gate. `pnpm-workspace.yaml` overrides pin every resolution (including the composer's own dependency) to the tarballs; the desktop runtime install resolves them from the packed package set, never the registry.
4. **Composer accessory seat.** `conversation.input.accessory` and `conversation.hero.modeActions` mirror the reference assembly; an unoccupied accessory seat hides its wrapper so committed card geometry is unchanged until an occupant registers. The `conversation.composer.dock` seat renders against the point-in-time session zone (the reference behavior), which is what lets the composer bundle's template chooser mount below the resident card on blank sessions; both extension seats and the hero cluster render only in Work mode through a boolean snapshot over the same `oristrat` settings scope the sidebar switcher writes.
5. **Pipe-backed webServer for bundle RPC channels.** The desktop host carries renderer requests over byte pipes with the listening webserver row disabled, so bundle host plugins that gate web registration on `webServer` (the Office PPT RPC channels among them) never registered and their requests fell through to the asset fallback (HTTP 405). `apps/desktop-host` now ships a `desktop-pipe-webserver` row: an in-process `webServer` stand-in that stores exact/prefix/fallback routes, mints one loopback-bound session cookie through the Connection index handshake (the pipe transport has no browser cookie jar), and dispatches matched pipe requests through node:http-shaped shims ahead of the asset fallback. Unit coverage lives in `apps/desktop/tests/pipe-webserver.spec.ts`.
